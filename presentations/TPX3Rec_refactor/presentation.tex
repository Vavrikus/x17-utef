	\begin{frame}{Motivation for Refactoring}
		\textbf{Original Codebase Limitations:}
		\begin{itemize}
			\item Heavy reliance on monolithic files and disconnected primitive C-arrays.
			\item Tight coupling between I/O, configuration, and physics logic.
			\item Repetitive event loop boilerplate across different execution steps.
		\end{itemize}
		\vspace{0.5cm}
		\textbf{New Architectural Goals:}
		\begin{itemize}
			\item \textbf{Encapsulation:} Group detector physics into robust structural models.
			\item \textbf{Polymorphism:} Standardize execution via a unified \texttt{Task} interface.
			\item \textbf{Separation of Concerns:} Isolate ROOT I/O state and \texttt{TEnv} parsing.
			\item \textbf{Maintainability:} Prepare for safe memory management and LLVM tooling.
		\end{itemize}
	\end{frame}
	
	\begin{frame}{Modernizing the Codebase Infrastructure}
		\textbf{Directory Standardization:}
		\begin{itemize}
			\item More typical names directory names for source files (\texttt{src/}) from the public API (\texttt{include/}).
		\end{itemize}
		
		\vspace{0.4cm}
		\textbf{LLVM Tooling Integration:}
		\begin{itemize}
			\item \textbf{\texttt{clangd}:} Custom \texttt{cmake\_wrapper.sh} maps the ROOT build, enabling accurate code-completion and jump-to-definition in VS Code.
			\item \textbf{\texttt{clang-tidy} \& \texttt{clang-format}:} Enforces a strict, ROOT-inspired formatting standard and flags memory leaks / legacy C-patterns.
			\item If \texttt{compile\_commands.json} are generated for ROOT, you can easily jump inside its source files to function definitions
		\end{itemize}
	\end{frame}
	
	\begin{frame}{Data Model Evolution: Deconstructing the God Object}
		\begin{columns}[T]
			\begin{column}{0.48\textwidth}
				\textbf{The Old Approach:}
				\begin{itemize}
					\item Relied on a monolithic \texttt{TPX3Rec\_nTuple} class containing over 100 loose arrays and branch pointers.
					\item Memory pre-allocated simultaneously regardless of the active task.
				\end{itemize}
			\end{column}
			\begin{column}{0.48\textwidth}
				\textbf{The New Core Models:}
				\begin{itemize}
					\item \textbf{\texttt{Cluster}:} Encapsulates topology, local-to-global transformations, and native bounding box/track logic.
					\item \textbf{\texttt{Coincidence}:} Aggregates clusters to compute 3D vertices, angular correlations, and target projections.
				\end{itemize}
			\end{column}
		\end{columns}
		
		\vspace{0.5cm}
		\textbf{Current Bottleneck \& Future Fix:} 
		To maintain ROOT serialization compatibility, \texttt{Coincidence} currently copies raw \texttt{Cluster} data into flat vectors. Future iterations will upgrade \texttt{Coincidence} to simply hold a \texttt{std::vector<Cluster>} natively.
	\end{frame}
	
	\begin{frame}{Execution Architecture: The Task Interface}
		The central steering macro (\texttt{runTPX3Rec.cxx}) now delegates execution to isolated, derived tasks.
		
		\vspace{0.3cm}
		\begin{itemize}
			\item \textbf{\texttt{Task (Base Class):}} Owns standard file initialization, standard branching, and finalization. Defines the pure virtual \texttt{Execute()} loop.
			\item \textbf{\texttt{SingleDet \& MergeTrees:}} Handles standalone calibrations and multi-detector file merging.
			\item \textbf{\texttt{GetCoincidences:}} Core physics loop detecting time-correlated clusters.
			\item \textbf{\texttt{AlignDetectors:}} Global spatial transformation and vertex generation.
			\item \textbf{\texttt{ProcessSimulation / FilterSimulation:}} Monte Carlo pipeline integration.
		\end{itemize}
	\end{frame}

	\begin{frame}{Identified Issues: Math \& Geometry}
		During the architectural audit, several geometric anomalies and legacy C++ traps were identified for future resolution:
		
		\vspace{0.3cm}
		\begin{itemize}
			\item \textbf{Type-Safe Math (\texttt{std::abs} vs \texttt{abs}):} The C++ \texttt{abs()} function silently truncates to integers. This likely causes unwanted rounding in functions like the Hough transform (already replaced with \texttt{std::abs()}).
			\item \textbf{Geometric Edge Cases:} 
			\begin{itemize}
				\item \texttt{Linearity} can currently evaluate to $< 1$ for perfectly straight diagonal tracks.
				\item \texttt{MaxDistance} adds 1 pixel assuming alignment with the X/Y axes, skewing distances by up to $\sqrt{2}$.
				\item \texttt{BorderHits} assumes hits lie exactly on the \texttt{GetRect} bounding box, cascading into \texttt{MaxDistance} inaccuracies.
			\end{itemize}
			\item \textbf{Asymmetric Cuts:} Exclusion of border tracks currently only applies to one of the two clusters in \texttt{CalculateVertex}.
		\end{itemize}
	\end{frame}

	\begin{frame}{Architectural Observations \& Future Roadmap}
		Beyond the core models, the codebase review highlighted several areas where the framework's boilerplate can be further optimized:
		
		\vspace{0.3cm}
		\begin{itemize}
			\item \textbf{TChain Design Question:} Detector data is currently split across parallel \texttt{TChain} arrays. A more robust ROOT paradigm would be multiplexing the detector ID into a single \texttt{TTree}.
			\item \textbf{Event Loop Overhead:} Functions like \texttt{SingleDet} execute redundant \texttt{SetBranchAddress} bindings on every iteration (related to converting \texttt{std::vector}s to C-style arrays).
			\item \textbf{Code Consolidation:} Duplicate, slightly divergent implementations of \texttt{FitTrack}, \texttt{Hough2D}, and \texttt{GetTargetProjections} need to be deduplicated.
			\item \textbf{Memory \& 3D Math Integration:} Swap manual heap allocations (\texttt{new[]}) for RAII arrays, and replace primitive variables with native \texttt{ROOT::Math} objects.
			\item \textbf{Documentation (Doxygen):} Progressively document the new API headers (\texttt{include/}), leveraging AI-assisted generation in VS Code to expedite writing boilerplate.
		\end{itemize}
	\end{frame}}
